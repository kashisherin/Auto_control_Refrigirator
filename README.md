# Predictive Adaptive Control of an Industrial Refrigeration System

A full-stack industrial control system simulation featuring a **backend physical thermal engine** and a **classy, modern interactive User Interface (UI)** with real-time refrigerator door controls, live telemetry, dynamic visual animations, and controller analytics.

---

## 🚀 Quick Start (Running the UI & Backend)

Run the main application:

```bash
python main.py
```

This will launch the backend simulation server and automatically open the **Interactive Dashboard UI** in your default web browser at `http://127.0.0.1:8000`.

To run as a native PySide6 desktop window:

```bash
python main.py --desktop
```

## 🏗️ Architecture: Backend Algorithms & Frontend UI

### 1. Backend Physics Engine (`backend/`, `models/`, `controllers/`, `experiments/`)
- **Thermal Plant Model (`models/refrigeration_model.py`)**: Lumped thermal capacitance equation $C \frac{dT}{dt} = Q_{\text{leak}} + Q_{\text{door}} - Q_{\text{cooling}}$.
- **Disturbance Model (`models/disturbances.py`)**: Extra thermal conductance ($UA_{\text{door\_extra}}$) applied when door opens.
- **Control Algorithms (`controllers/`)**:
  - `open_loop`: Fixed baseline compressor cooling power (Phase 1).
  - `on_off`: Bang-Bang hysteresis controller (Phase 4).
  - `pid`: Standard PID with anti-windup clamping and derivative low-pass filter (Phase 5).
  - `adaptive_pid`: Gain-scheduled adaptive PID with dynamic disturbance feedforward (Phase 8).
  - `predictive`: Model Predictive Control (MPC) with pre-cooling disturbance horizon optimization (Phase 9+).
- **Performance Metrics (`experiments/metrics.py`)**: Energy consumption (kWh), MAE (°C), RMSE (°C), peak spike (°C), and duty cycle (%).

### 2. Classy Frontend UI (`gui/static/`)
- **Interactive 3D Refrigerator Model**: Animated hinged door that opens and closes smoothly when clicked, showing interior lighting, cold mist fog, and thermal color gradients.
- **Interactive Door Toggle**: Click the **`🚪 OPEN REFRIGERATOR DOOR`** button directly from the UI to trigger real-time heat disturbance in the backend!
- **Real-Time Telemetry Dashboard**: Live charts rendering Chamber Temp vs. Setpoint, Compressor Power (W), and shaded Door Open intervals.
- **Algorithm Switcher**: Seamlessly switch between Open-Loop, ON/OFF, PID, Adaptive PID, and Predictive MPC on the fly.

**Why this structure?** The GUI, the physical plant, the controllers and
the prediction logic are kept in separate folders/modules on purpose.
A controller should never need to know *how* the temperature is
computed, and the plant should never need to know *which* controller
is driving it. This is what lets Phase 12 fairly compare ON/OFF vs PID
vs Adaptive PID vs Predictive Adaptive Control on the *exact same*
plant and disturbance code.

## 2. The physical model

The chamber is treated as a single lumped thermal mass (a "thermal
capacitor"), exactly like a first-order RC circuit in the
electrical-thermal analogy used in Unit 1 mathematical modelling:

```
C * dT/dt = Q_leak + Q_door - Q_cooling
```

| Symbol       | Meaning                                            | Units |
|--------------|-----------------------------------------------------|-------|
| `T`          | chamber air temperature                             | degC  |
| `C`          | effective thermal capacitance                       | J/K   |
| `Q_leak`     | heat leaking in through the insulated walls         | W     |
| `Q_door`     | EXTRA heat entering because the door is open        | W     |
| `Q_cooling`  | heat removed by the refrigeration unit              | W     |

Both heat-gain terms use a simple linear (Newton's-law-of-cooling)
conductance model:

```
Q_leak = UA_leak       * (T_ambient - T)      always present
Q_door = UA_door_extra * (T_ambient - T)      only while the door is open
```

`Q_cooling` in Phase 1 is a **fixed constant**, not yet a controller
output. It's deliberately sized so the natural steady state with the
door closed lands exactly on the setpoint:

```
Q_cooling_max = UA_leak * (T_ambient - T_setpoint)
```

This lets us test the plant and disturbance model completely on their
own, before any control logic is introduced in Phase 4.

## 3. Simulation-scale assumption (important, please read)

A real industrial cold room has a thermal time constant of hours,
because of its large air volume, product mass and insulation. Modelling
that faithfully would need a multi-hour simulation for a single door
event to show up clearly on a graph.

For this mini-project we use a **smaller virtual chamber** (lab-scale
box, not a warehouse) so the pull-down + disturbance + recovery cycle
fits inside a few thousand seconds of simulated time. The physics
(first-order thermal system, linear heat-leak conductance) is identical
in form to a real industrial chamber -- only the numeric values of `C`
and `UA` are scaled down. This is stated explicitly here, and again as
comments in `config/parameters.py`, so it is never confused with a
claim about a real industrial system.

## 4. Parameters used in this run

| Parameter | Value | Meaning |
|---|---|---|
| `T_INITIAL_DEGC` | 25.0 degC | chamber starts at ambient ("cold start") |
| `T_SETPOINT_DEGC` | -18.0 degC | frozen cold-storage target |
| `T_AMBIENT_DEGC` | 25.0 degC | surrounding room temperature |
| `C_THERMAL_J_PER_K` | 20,000 J/K | effective thermal capacitance (assumption, Section 3) |
| `UA_LEAK_W_PER_K` | 8.0 W/K | wall/insulation leak conductance (door closed) |
| `UA_DOOR_EXTRA_W_PER_K` | 40.0 W/K | extra conductance added while door is open |
| `Q_COOLING_MAX_W` | 344.0 W | fixed cooling power, derived so steady state = setpoint |
| `DT_SECONDS` | 1.0 s | Euler integration time step |
| `SIM_DURATION_SECONDS` | 12,000 s (200 min) | total simulated time |
| `DOOR_OPEN_AT_SECONDS` | 8,000 s | when the door opens in this demo |
| `DOOR_OPEN_DURATION_SECONDS` | 90 s | how long the door stays open |

All of these live in `config/parameters.py`, with the full derivation
commented next to each one -- change them there, not inside the model
files.

## 7. Expected output

Console output (numbers will match exactly if you haven't changed
`config/parameters.py`):

```
Saved data to data/simulation_data.csv

--- Phase 1 sanity check ---
Initial temperature      : 25.00 degC
Setpoint                 : -18.00 degC
Temperature just before door opens : -16.25 degC
Peak temperature during/after door-opening event : -9.62 degC
Saved plot to data/phase1_temperature_response.png
```

A window will pop up (and `data/phase1_temperature_response.png` is
saved to disk) showing:

- An **exponential pull-down** from 25 degC toward the -18 degC setpoint
  (classic first-order step response -- this is the "charging a
  capacitor" shape from circuit theory, just for heat instead of
  charge).
- A **sharp temperature spike** when the door opens at t = 8000 s
  (133.3 min), because `UA_door_extra` briefly makes it much easier for
  ambient heat to reach the chamber than the fixed compressor power can
  remove.
- A **decay back toward the pre-disturbance trend** once the door
  closes 90 seconds later, because the plant returns to its original
  heat balance -- this is the system's own open-loop stability, *not*
  active control.

`data/simulation_data.csv` contains the full time history
(`time_s`, `temperature_degc`, `door_open`, `cooling_power_w`) for
reuse in later phases (metrics, comparison plots).

## 8. Interpreting the result

Two things this phase deliberately shows you:

1. **The plant is a stable first-order system.** With the door closed,
   any starting temperature converges toward the same steady state
   (-18 degC here, by design). This matches classical control theory:
   a stable pole at `s = -UA_leak / C`.
2. **A fixed-power, no-feedback ("open-loop") system cannot reject a
   large disturbance quickly.** During the 90-second door-opening
   event, the temperature rises by roughly 6-7 degC, and it takes a
   long time afterward to fully settle back down -- because nothing is
   actively increasing the cooling effort in response to the error.
   This is exactly the gap that Stage 1 (ON/OFF), Stage 2 (PID) and
   later adaptive/predictive control (Sections 5-8) are meant to close.
   Keep this plot -- it will be your baseline "no controller" reference
   when you build the controller comparison in Phase 12.

## 9. Troubleshooting

| Problem | Likely cause / fix |
|---|---|
| `ModuleNotFoundError: No module named 'pandas'` (or numpy/matplotlib) | Activate your venv and re-run `pip install -r requirements.txt`, or `pip install numpy pandas matplotlib` directly. |
| `ModuleNotFoundError: No module named 'config'` or `'models'` | Run the script from inside the `refrigeration_control/` folder (`cd refrigeration_control` first), not from one level up or down. |
| Plot window never appears (headless server / SSH without X11) | The script still saves `data/phase1_temperature_response.png` to disk even if the interactive window can't open -- open that PNG directly instead. |
| Numbers don't match Section 7 exactly | Check you haven't edited `config/parameters.py`; also confirm `DT_SECONDS = 1.0` (a much larger time step will change the Euler-integration result slightly). |
| Temperature runs away instead of settling | This would indicate the plant is unstable (e.g. `UA_leak <= 0` or `C <= 0` in `config/parameters.py`). With the default parameters this system is always stable, since it's a negative-feedback (self-correcting) heat-leak term. |
